Which code is good at what

Twelve codes on the same tests, from the same starting states, measured the same way. Two questions per test: how long a set-up takes to reach a given accuracy, and how fast its error falls as the grid is refined.

Best at each job: least time to the accuracy

  • Smooth waves (entropy, alfven, alfven oblique): AthenaPK PPM/HLLD/RK3, GLM (1×), Athena++ PPM/HLLE/RK3 (4.2×), Athena++ PPM/HLLD/RK3 (5.3×); 33 of 40 set-ups reached the accuracy on every one.
  • Field transport (field loop novz, field loop 3d): gPLUTO parabolic/HLLD/RK3, GLM (1.8×), AthenaK PPM/HLLD/RK3 (2.2×), AthenaPK PPM/HLLD/RK3, GLM (2.2×); 28 of 40 set-ups reached the accuracy on every one.
  • Shocks (brio wu, brio wu rotated, blast 2d b0, blast 2d b50): AthenaK PPM/HLLD/RK3 (2.4×), Abel et al. GLM HLLD (3×), Abel et al. GLM HLLD, fixed (3.6×); 35 of 40 set-ups reached the accuracy on every one.
  • Vortices and instabilities (orszag tang, rotor, kh uniform): Cholla PPMC/HLLD/VL, CT (1×), Abel et al. GLM HLLD (1.5×), AthenaK PPM/HLLD/RK3 (1.7×); 33 of 40 set-ups reached the accuracy on every one.
  • Reconnection (current sheet, gem): Abel et al. GLM constant cₕ (3.2×), Abel et al. GLM f16/HLL (production) (3.2×), Abel et al. GLM f16/HLL (production), fixed (5.9×); 14 of 40 set-ups reached the accuracy on every one.

1 · Time to a given accuracy

For each test, the error to reach is that of a standard second-order code, AthenaK PLM/HLLE/RK2, at 256² (its value is in each column's tooltip). Each cell is the time a set-up needs for that error at the end of the test: on one H100 for the GPU codes, on 128 cores for the CPU codes (their speed per core, assuming perfect scaling). The small number is how many times the fastest set-up on that test. A set-up's speed is measured on its largest finished 3D run, where a GPU is fully used; the grid it needs is read from its errors on the grids it ran. 3 · Speed: cell updates per second

The speed behind the times of section 1: how many cells a set-up advances by one step each second, on its largest finished 3D run (the median over the 3D tests at that grid, by the code's own clock), on one H100; a set-up on two GPUs is counted per GPU. CPU codes: their speed per core times 128, assuming perfect scaling, as in section 1; AREPO and GIZMO ran no 3D test, so theirs is from their planar runs. Beside each bar: the set-up's time to the accuracy, from section 1 (median × the fastest, and the tests it reached of those it finished). GPU and CPU bars share one scale.

A fast cell update is not a fast answer: a step does different work in each set-up (reconstruction, Riemann solver, stages per step), the steps are of different length, and each cell buys a different accuracy. Abel et al. GLM tiled LLF (original path) makes the most cell updates per second, 8.8× as many as Cholla PPMC/HLLD/VL, CT; yet Cholla PPMC/HLLD/VL, CT reaches the accuracy in the least time (a median 1.2× the fastest on each test, against 10×).

How this is measured

  • Every code starts from the suite's own initial state and writes the same outputs; the error is against the exact solution or a 4096² reference run.
  • Each code runs a matched set-up (second order, an HLL-type solver, as close to Abel et al.'s kernels as it allows) and a best one (its strongest standard choice).
  • Precision: Abel et al.'s kernels keep their state in Float32 (the f16 kernels compute in Float16); every other code runs in fp64. GPU: one NVIDIA H100; set-ups on two GPUs are counted per GPU.
  • A run that stopped or turned non-finite counts as not reaching the accuracy at that grid; the test pages say why each stopped.
  • Seed 42, the end time of each test. Data: work_precision.json; the five newest codes as fetched 2026-11-08 09:57 UTC.
