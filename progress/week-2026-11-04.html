Five more codes now run the whole suite from the same starting states as the others: AthenaPK, Cholla and gPLUTO on H100s, Enzo and Phantom on CPUs, each with a matched set-up (second order, an HLL-type solver) and its best one. 1,413 of their 1,420 runs have finished.

How to read it. Stopped: the code stopped itself or its state turned non-finite; each is recorded with the code's own reason. Time to accuracy: how long the set-up takes to reach a fixed error, as a multiple of the fastest set-up on each test, median over the tests it reached (in brackets: tests reached of those it finished; section 2 explains the measure). Order: how fast the error falls with resolution on the smooth-wave tests (2 for a second-order scheme).

What stands out. Cholla PPMC and AthenaPK PPM/HLLD are among the fastest of all to the accuracy. Most stops are the codes' own checks: Cholla stops when div B passes a fixed limit; AthenaPK PPM/HLLD turns non-finite on the decay test on every grid and seed; Phantom's stability check stops the field loops (its own divergence projection removed 26 % of the magnetic energy by the first output, so it runs without it). Cholla and gPLUTO need two H100s for 3D at 512³.

02Time to a given accuracy, and speed per cell

How it is measured. For each test we fix a target error: the error AthenaK PLM/HLLE/RK2, a standard second-order set-up, has at 256². For each set-up we find the grid on which its error falls to that target (interpolated between the grids it ran), and the time it needs there: its steps times the cells, divided by its speed (cell updates per second on its largest 3D run, on one H100 or 128 cores). The time is then divided by that of the fastest set-up on the test; the plot shows the median over the 14 tests.

What it shows. Speed per cell does not decide the time to an answer. Abel et al. GLM tiled LLF (original path) makes the most cell updates per second, 8.8× as many as Cholla PPMC/HLLD/VL, CT, but needs 10× the fastest time against 1.2× for Cholla PPMC/HLLD/VL, CT. A more diffusive scheme needs a finer grid for the same error, and in 2D the work grows as the cube of the grid (cells × steps). On Orszag–Tang:

Test by test. Two plots for each test. The first is the plot above with the time in seconds to that test's target error; the marker shape is the first grid that reaches the target, so it also shows the memory each set-up needs. The two axes are linked: time = steps × cells ÷ speed, so time × speed is the work, in cell updates, a set-up needs for the target (the grey diagonals are equal work, a factor of 10 apart). Moving along a diagonal trades speed for time at the same work; a set-up below another's diagonal needs fewer cells or fewer steps. Speeds are the same on every test except for codes with no 3D run (AREPO, GIZMO), so from test to test the points mostly move up and down.

The second plot is the full curve behind it: the error against the time to solution on every grid, one line per code (the code's set-up with the least time to the target on that test), the target as the dashed line. Where a line crosses the target is the time in the first plot; the time there is interpolated between the two grids on either side of it, so a set-up that passes well below the target on a grid is not charged for that whole grid. A set-up already below the target on its coarsest grid has only an upper limit (the arrow); one that never reaches it is in the band at the top of the first plot.

What was run. In AthenaK, Athena++ and Abel et al.'s kernels, all four pairs of reconstruction (PLM, piecewise linear; PPM, piecewise parabolic) and Riemann solver (an HLL-type one, or HLLD), at one time integrator: 560 complete runs.

How to read it. Each entry is how much faster the set-up reaches the target error of section 2 after the change, median over the tests: PPM in place of PLM (with the HLL-type solver), HLLD in place of HLL (with PLM), and both. The last but one column is how much more a cell update costs with PPM than with PLM.

What it shows. In AthenaK and Athena++ PPM pays: the coarser grid it needs more than covers its cost per cell (on the smooth waves Athena++ PPM converges at about fourth order). In Abel et al.'s kernels a PPM cell update costs several times a PLM one, so PPM does not pay on most tests; HLLD does, in every code. The figure shows each test.

04Convergence measured without the exact solution

Why. In a real problem the true solution is unknown, and convergence is judged from the runs themselves. We tried three ways on the 13 planar tests and compared each with the true error, which is known there (the exact solution, or AthenaK at 4096²): (1) the set-up's own finest grid as the reference; (2) the difference between grid N and 2N, whose fall with N gives the order; (3) Richardson extrapolation, which combines the three finest grids, assuming the error falls as N−p, into an estimate of the converged answer.

testsown finest ÷ true errororder from differencesorder against truthRichardson estimate ÷ true errorRichardson gain
Smooth waves0.852.02.01.11.1
Shocks0.610.70.81.90.6
Kelvin–Helmholtz, current sheet0.521.20.10.430.98

What it shows. Against its own finest grid a set-up looks better than it is: its error seems 15 % smaller on smooth waves, 39 % with shocks, 48 % on Kelvin–Helmholtz and the current sheet. Grid differences give the true order on smooth waves; on Kelvin–Helmholtz and the current sheet they shrink at order 1.2 while the true error barely falls (order 0.1): the grids agree with each other, not with the truth. Richardson's estimate of the error is good on smooth waves (ratio 1.1), but its extrapolated answer is no nearer the truth than the finest grid (gain 1.1; below 1 with shocks): the limiters change the error's pattern from grid to grid. In the figure, GIZMO's true error on the Alfvén wave stops falling at 64² (about 0.1 %), while against its own finest grid it seems to converge: an own-grid reference cannot see a code converging to a wrong answer.
